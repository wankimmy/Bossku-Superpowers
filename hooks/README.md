# BosskuAI plugin hooks

Mechanical gates for the disciplines in `AGENTS.md`. Declared in [`hooks.json`](hooks.json), wired through `.claude-plugin/plugin.json` (`"hooks"`), and run with plain `node` (built-ins only, nothing to install). Every hook is fail-open: an internal error exits 0 and never wedges a session.

| Event | Script | What it does | Off switch |
|---|---|---|---|
| SessionStart | `session-start.mjs` | Prints the compact harness contract (indicator, routing, DESIGN.md pointer, gates, memory) so it reaches the model in every repo, and again after `/compact`. | remove from hooks.json |
| PreToolUse `Bash\|PowerShell` | `guard.mjs` | Denies commands that destroy uncommitted work (`git reset --hard`, force push or `+ref` push, `git clean -f`, `git checkout .` / `-f` / `--`, `git restore` of the working tree), wipe data (`migrate:fresh`, `DROP TABLE`, `flushall`), take down the runtime (`docker compose down`, `kill -9`, `systemctl stop`), delete outside the project (`rm -r`, `Remove-Item -Recurse` or its short forms `-r` / `ri`, `rd /s`, `find ... -delete` on an absolute, `~` or `$HOME` path, quoted or not, or on a protected path; an absolute path strictly inside the project or the OS temp folder is fine, even when the project sits under `/home`, `/Users` or `C:/Users`), or pipe a remote script into a shell. Git options in any order (`git reset -q --hard`, `git clean --force`, `git branch -d -f`) and global options (`-C`, `-c`, `--no-pager`) are looked through, the quoted body of `bash -c`, `pwsh -Command` and `cmd /c` is judged too, a leading `sudo` / `env` / `nohup` / `time` does not hide a command, and a lone `&` splits a command like `;` does. The model is told to hand the command to the user with recovery steps. | `BOSSKU_GUARD=off` |
| PostToolUse `Write\|Edit\|MultiEdit\|NotebookEdit` | `post-edit.mjs` | Syntax-checks the written file (JSON, `node --check` including ESM `.js`, `php -l` with the first `php` on PATH, never one in the current folder, Python via `compile()` on the first working of `BOSSKU_PYTHON`, `python3`, `python`, `py`; no `__pycache__` is written). A `.js` whose first error is a lone `<` is taken for JSX and passes (merge-conflict markers like `<<<<<<<` are still reported). A Flow `.js` with `import`/`export` keeps the plain check, which node does not parse, so it passes too; a Flow file without `import`/`export` is checked as plain JS. Lints UI and copy files for AI tells: hard tells (placeholder people and companies, filler text, fake-perfect uptime figures) come back as exit 2; soft tells (an uptime figure with no source, em-dash, filler verbs, purple gradients, glass everywhere, Inter default, placeholder image hosts, text logo walls) as a warning. The patterns are `HARD` and `SOFT` in `post-edit.mjs`. The lint skips `skills/`, `docs/`, `agents/`, `references/`, `.claude/`, `.bossku/`, memory folders, vendored and build folders, a few tool folders (`.git/`, `ai-skills/`), and the contract files (`SKILL.md`, `AGENTS.md`, `CLAUDE.md`, `CHANGELOG.md`, `LICENSE.md`, `CONTRIBUTING.md`, `SECURITY.md`). Files under `~/.claude` (workflow scripts, memory) and the OS temp folder get no check at all, unless the session itself runs inside that folder. | `BOSSKU_POST_EDIT=off`, `BOSSKU_SLOP_LINT=off` |
| Stop | `stop-gate.mjs` | If source files were edited this turn and no verification command ran after the last edit, the turn cannot end: the model must run the pass signal or state exactly what is unverified. Doc-only turns pass, and so do edits under `~/.claude` or the OS temp folder (workflow scripts, memory, scratch files) unless the session itself runs inside that folder; other repos and `/add-dir` folders count as usual. Only the end of the transcript is read. Adds the 390/1440 screenshot reminder when UI files changed. | `BOSSKU_STOP_GATE=off` |

`scripts/shot.mjs` is the visual-verification helper the stop gate points at: `node "<root>/scripts/shot.mjs" http://localhost:3000` (`<root>` is the folder above `hooks/`; the hooks print the real path) writes `phone-390.png` and `desktop-1440.png` under `.bossku/shots/<stamp>/` for the model to Read. It runs `npx --no playwright screenshot`: `--no` means npx never downloads a package on its own. If Playwright is not a dependency of the project, the script stops and prints the install line for you to run once (`npm i -D playwright && npx playwright install chromium`). `bossku init` does not add `.bossku/shots/` to `.gitignore`, so add it yourself if you do not want the PNGs committed.

The Python helper hooks have their own switches: `BOSSKU_VERIFY_GATE=0` for the Python verify gate (it is the Stop hook only after `bossku install --no-harness`; the Node stop gate ignores it), and `BOSSKU_RESUME=off` for the two hooks that read Codex's session files (see [`SECURITY.md`](../SECURITY.md#hooks)).

## Manual tests

```bash
echo '{"tool_name":"Bash","tool_input":{"command":"git reset --hard"}}' | node hooks/guard.mjs      # -> deny JSON
echo '{"tool_name":"Bash","tool_input":{"command":"git status"}}' | node hooks/guard.mjs            # -> nothing
echo '{"tool_input":{"file_path":"/path/to/Hero.tsx"}}' | node hooks/post-edit.mjs                   # -> lint result
node --test tests/hooks.test.mjs                                                                     # full suite
```

`python -m unittest discover -s tests` also runs the Node suite when `node` is on PATH.

## Second layer

`bossku install`, `bossku update` and `bossku hooks install` wire these four hooks into `~/.claude/settings.json` for an install without the plugin. It needs `node` on PATH and a checkout of this repo (`--root`, `BOSSKU_ROOT`, or the folder `bossku` runs from; `bossku update` without `--root` uses the checkout saved by the install): every command runs a script from that checkout's `hooks/` folder and ends in `--bossku-harness`, and the Node stop gate replaces the Python `verify-gate`, so there is never a second Stop gate. `bossku install --no-harness` leaves them out and takes ours out again (the Python `verify-gate` is the Stop gate then); later `install`, `update` and `hooks install` runs keep that choice, and `--harness` turns them back on. With no checkout or no `node`, `hooks install` wires none of the four Node hooks (the sync, skill-hint and session-brief hooks still go in, and so does the Python `verify-gate` unless a Node Stop gate is already there) and leaves a harness that is already there alone. Use the wired hooks or the plugin, not both, or each hook runs twice (`bossku doctor` warns when both are on). The same install also adds a `permissions.deny` list for the unambiguous cases (`git reset --hard`, `git clean -f`, `git push -f`, `migrate:fresh`, `db:wipe`, `docker compose down`, `docker-compose down`, `docker system prune`), next to any entries you already have, and `bossku hooks uninstall` removes both again. Those deny rules hold even when the plugin is disabled or `BOSSKU_GUARD=off`. Each entry is a `perm` on a rule in `guard.mjs`; `DENY_RULES` in `bossku/hooks.py` is the installer's copy and must stay equal to those `perm` strings. `tests/hooks.test.mjs` fails when the `perm` list changes or an entry is not matched by its own guard rule.
