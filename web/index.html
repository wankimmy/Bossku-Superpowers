Free and open source, for Claude Code, Codex, Cursor, OpenCode and OMP

Skills tell your agent what to do. Bossku checks that it did.

Hooks that refuse destructive commands, ask before a push, send the agent back when it edited code and ran no check after, and show your saved notes when the next session starts. Strongest in Claude Code; Codex, Cursor, OpenCode and OMP get the skills and part of the hooks.

Why Bossku Superpowers

  1. Checks.

    Hooks, not just advice

    A skill is text the agent may or may not follow. Bossku adds hooks that act at the moment it counts. In Claude Code, git reset --hard, a plain force push and similar commands are refused, a git push waits for your yes, and a turn that edited code with no check after it is sent back once.

  2. Remembers.

    Your rules reach tomorrow

    The agent is told to save the rules and decisions you give as notes. In Claude Code the newest notes show when the next session starts, and every 50 tool calls the agent is asked to turn useful lessons into small skills. With Obsidian storage, notes and learned skills stay out of the code repo.

  3. Travels.

    One install for your tools

    bossku install makes the same skills available to Claude Code, Codex, Cursor, OpenCode and OMP, and writes seven subagent contracts for Claude Code, Codex, Cursor, OpenCode and Devin. The full hook set runs in Claude Code; the command guard also runs in Codex, Cursor and OpenCode.

  4. Measured.

    Numbers in public, with the limits

    Benchmarks with and without Bossku are published with their intervals and their weak spots. We found none in the READMEs of Superpowers, ECC, the Karpathy guidelines or Anthropic's skills.

Agent action: git push

git push origin main

Asks you first

In Claude Code the push waits for your yes. The same goes for a PR merge, npm publish, vercel --prod, terraform destroy and similar. A push hidden inside a script is not seen. Claude Code's own permission rules can do this too; Bossku ships the rule set ready-made, and its ask still shows when you have allowed commands broadly. Codex and OpenCode 1 refuse instead of asking.

Agent action: git reset --hard

git reset --hard

Refused

Commands such as git reset --hard, a plain force push or rm -rf ~ are blocked, and the agent is told to give you the exact command and recovery steps to run yourself. A --force-with-lease push asks instead. Runs in Claude Code; the Codex, Cursor and OpenCode versions are unit-tested against each tool's hook format, not yet run inside those apps.

Agent action: saying done without running code

Edited 3 files. Done!

Sent back once

If the agent changed code and ran no test, lint, build or run after its last edit, the stop gate sends it back once. It checks that something ran, not that it passed. Switch it off with BOSSKU_STOP_GATE=off.

Does it really help?

Real agents, the same tasks, with and without Bossku Superpowers. The chart shows two-session tasks: a rule is set in one session and needed in the next. Read the setup first: the "without" runs had no Bossku setup, no CLAUDE.md and Claude Code's own auto memory switched off. The Claude runs still used the tester's own Claude Code config, which listed 20 skills and 2 plugins at start.

81%

An acceptable skill was ranked first on 158 requests the router was never tuned on, against 56% for a keyword baseline that uses only skill names and descriptions. Acceptable skills were labelled by AI models, not people. Not compared with Claude Code's own skill picking. With a real agent, an acceptable skill was opened for 45% of 60 requests.

62% →to 92%

HumanEval problems passed by the small Nemotron 3 Nano 30B, a model that usually skips running its code: 25 of 40 without, 37 of 40 with. The runs without Bossku were done on other days.

1.0× to 4.7×

The catch: about the same or more tokens per run, highest on models that checked the least before. On coding and harder tasks the three open models tested showed no clear change in pass rate; Claude models were not run on those.

What this does not show: whether Bossku beats Claude Code's own memory or a rule you wrote in CLAUDE.md. That was not tested. Samples are small, so read each result with its interval. $ bossku learn list

New in v2.12.0

Auto-learn

In Claude Code, every 50 tool calls a Stop hook sends the agent back once and asks it to save useful lessons as small skills. Every fifth pass asks it to merge near-duplicates and fix rules that a newer rule contradicts.

Learned skills live with your project notes: in your Obsidian vault in Obsidian mode, or in the project's .bossku/memory/skills folder by default. Only bossku learn apply writes them, and it rejects skills with secrets, prompt-injection phrases or destructive commands, using fixed patterns. Archiving moves a skill aside instead of deleting it.

Off switch: BOSSKU_AUTO_LEARN=off

A security gate, on by default

Your agent is told to give every change a security pass across seven layers: business process, design, code, data and privacy, supply chain, infra and CI, and AI agents, and to check vulnerabilities against live feeds (OSV.dev, GitHub Advisories, CISA KEV) rather than memory. Nothing checks that it really did.

In Claude Code, a hook sends the agent back once when a turn changed code, dependencies or infra and the reply has no verdict line. It checks that the line is there; it does not run a scanner.

Security gate: PASS | BLOCK

Off switch: BOSSKU_SECURITY_GATE=off

Set it up in a few steps.

You need Python 3.11+ and Git. The same commands work in Windows PowerShell; if bossku is not found, use python -m bossku instead.

  1. Get it

    git clone https://github.com/wankimmy/Bossku-Superpowers
cd Bossku-Superpowers
pip install -e .

  2. Set up your machine

    bossku install

    Copies the skills, writes the subagent contracts for each tool you have set up, and turns on the hooks. Want notes in Obsidian? Add --vault "/path/to/your/Obsidian/Vault" --memory-storage obsidian.

  3. Set up a project

    cd /path/to/your/project
bossku init .

    Adds a Bossku block to AGENTS.md, a CLAUDE.md that imports it, and small .omp/ and .bossku/ files.

  4. Check it

    bossku doctor --project .

    Prints doctor: ok, or the issues found and what to fix.

  5. Use your agent

    Open the project and start your agent as usual. No magic word: the hooks run on their own. Mostly you will not notice anything, until it stops a mistake. Remove the hooks with bossku hooks uninstall (also turn off the Bossku plugin if you enabled it in Claude Code), or Bossku's user-level setup with bossku uninstall --purge; project files and notes stay.
