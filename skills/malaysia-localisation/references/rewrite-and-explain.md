# Rewrite and explain

Use for iterative rewrites and public technical explanations. These are editorial
choices informed by feedback on one casual BM/rojak draft, not population-wide
language rules. Formal BM, English-only and other speakers' samples take priority.

## Carry corrections forward

Treat an explicit replacement as stronger evidence than an earlier generated
phrase. Keep a small working list of the draft's chosen nouns, verbs, comparison
structure and audience address. Apply it to equivalent passages, not a global
search-and-replace. A later full rewrite includes all accepted edits; returning
only the changed sentences is suitable when that is the requested scope.

Examples from this type of voice:

| Editorial choice | When it helps |
|---|---|
| AI agents rather than agents on first mention | Readers need to know what kind of agent is being compared. |
| Aku check tiga benda | The speaker explicitly prefers check for the measurements being inspected. |
| yang pakai pack tu dengan yang tak pakai | Both comparison groups are clear in a spoken BM sentence. |
| percentage rather than peratus | This speaker chose the English term in a rojak draft. |
| tak guarantee utk semua task yang korang bagi | The caveat preserves the chosen audience address and absence of a guarantee. |

Do not make check a replacement for every test, or turn all agents into AI
agents: a sales agent is a different referent. Percentage and peratus are both
valid in the appropriate brief. Use utk only when that shortform is established
or requested; casual public copy can otherwise use untuk. Don't introduce
korang into a one-to-one reply or replace a supplied formal address.

## Repair meaning before rhythm

When a reader says 'tak faham', changing vocabulary alone may leave the gap.
State who or what is being discussed, what happened, and what is being checked.
Keep familiar English domain terms where they help; explain the unfamiliar
relationship in everyday language instead of replacing every technical noun.

- Compressed label: 'Dalam test ingat rules antara sessions'.
- Clearer, if that is the supplied test: 'Bila sambung kerja dalam session lain,
  AI agent masih ikut rules yang diberi sebelum ni? Itu yang aku check.'

This describes behaviour, not a claim that the model has internal persistent
memory. Do not invent how rules were stored, restored or scored. More generally,
observing behaviour does not establish its cause or the underlying mechanism.

## Give numbers a meaning

Keep the model, metric, condition, direction, units and uncertainty attached to
the value. Put a short explanation before the numbers if the metric is unfamiliar.
For percentages, name the denominator when supplied: percentage of runs, tasks,
rules or answers. If only a score is supplied, call it a score and ask what it
measures when that missing definition matters; never guess a denominator.

'Percentage runs yang langsung tak run code turun dari 100% ke 17%' explains
the unit and preserves a negative metric. Don't invert it into a success rate
unless the source establishes exhaustive categories. Running code does not by
itself mean the code passed tests; passing tests is not a guarantee for every task.
Keep these measures distinct without making the post sound like a report.

## Match the evidence task

For a wording-only rewrite, work from supplied material. Do not add a fact-check
workflow or copy generic warnings into every casual post. A request to explain
the experiment or decide if it is 'legit' goes beyond localisation: inspect the
method, scripts, scoring and results through available source tools.

A with/without comparison does not establish identical tasks, model versions,
tools or budgets. Describe controls, sample counts and repetitions only when
documented. If results used different token budgets, don't present them as a
controlled test of skills alone. HumanEval being named does not verify this
particular implementation, task subset or scoring method.

Where relevant, distinguish a standard benchmark from a custom test and the
author's experiment from an independent replication. Missing evidence means
the result remains unverified; it does not prove the test is invalid. Name the
specific missing detail and ask for the methodology rather than declaring the
experiment fair, statistically significant or reproducible.

Keep a source-access limitation in a short note to the user, outside publishable
copy. If a requested method paragraph cannot be written from evidence, say so
instead of filling it with a checklist disguised as the author's experiment.
Supported sections can still be drafted. Preserve a supplied 'possibly noise'
as a possibility; do not promote it to a confirmed explanation or silently erase it.

## Finish in the requested scope

Read the opening, comparison, results and caveat in the same voice. Keep enough
detail to make the idea understandable; brevity is not a reason to hide meaning.
For a full thread, return the complete updated sequence in a sensible order.
Retain links and the requested call to action. Do not add annotations, commentary,
alternate headlines or follow-up questions inside publishable copy unless asked.
When exact structured feedback markers are requested, preserve that syntax.
