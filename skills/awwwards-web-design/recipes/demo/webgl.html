WebGL recipes test harness

This page is a neutral test harness, not a design template. It uses system-ui, black on white, and labelled sections so the two recipes can be checked in isolation: three-hero.js (section 1) and webgl-image-hover.js (section 2).

Every image and the hero poster are plain HTML and render without JavaScript. The WebGL layers only replace them visually once they have drawn a frame.

1. three-hero.js: poster first, then a lit procedural object

The stage below is sticky inside a 200svh track. Scrolling through it scrubs the camera. On a fine pointer, moving the mouse gives a few degrees of parallax. Under reduced motion there is one still render and nothing else.

Section 1 stage (poster: a frame rendered by three-hero.js)

2. webgl-image-hover.js: move the pointer across each image

A still pointer leaves the picture untouched. Speed drags it locally. Each image covers a different mapping case.

3. Status and lifecycle

ready is true once a WebGL layer is live. False means the plain HTML fallback is showing, which is correct under reduced motion, on touch (hover recipe only), without WebGL, or when the CDN is blocked.
