# Evidence-gated upgrade: sources, current system and baseline

Reviewed on 2026-11-17.

## Scope and method

The goal is more independently verified task completion from one user instruction, with gates that check real outcomes, and no added orchestration. Bossku stays a skill collection plus a router. A change is kept only when a measurement supports it.

Each claim is labelled by evidence kind: **controlled experiment** (a run with a comparison), **observational analysis** (a review or audit of existing work), or **engineering guidance** (a vendor or practitioner recommendation with no measured effect). Measured facts about this repo are kept apart from hypotheses, which are only ever things to test.

Reading caveat: every web source was read through the fetch tool's summary, not the original text. Numbers are therefore "as reported by the reader". Two OpenAI pages (B2, B3) returned HTTP 403 and were not read, so nothing from them is used. H1 and H2 were read through page summaries by a separate reader. Check every number against the papers' tables before quoting it anywhere else.

### What the sources agree and disagree on

- **Self-correction needs an outside check.** R5, R8 and R9 agree that re-checking helps when the feedback is external and reliable (tests, execution), and that a model judging only itself does not reliably improve. R4 reports large gains from self-feedback on preference-scored tasks, which points the other way. The gap is task type and scoring, so for a coding agent it is unresolved.
- **Simpler pipelines can match agents at lower cost.** R7's fixed pipeline reached 32.00% at about USD 0.70 per issue. That is inside the USD 0.45 to 1.62 range of the agents it lists, so "cheaper" holds only against some of them. D1 advises the simplest solution. H1 found planning mainly cut cost for the two strongest models, not raised success.
- **Structure helps weaker models more than stronger ones.** In H1, planning helped the smallest model by 11.6 points, predefined tools by 15.0, and bash-only was better for the largest model. R6 shows interface changes moving results on GPT-4 Turbo. H2 shows the gain from harness fixes shrinking as the window grows. These come from different setups, so they are not one effect.
- **Public benchmark scores have contamination and grading problems.** R7 notes possible training-data contamination it cannot check. D5 reports grader bugs moving one result from 42% to 95% (an anecdote). B1 says human filtering checked the tasks. B2 and B3 would bear on this, but they were not read, so no flawed-test figure is used here.
- **Guidance documents are not experiments.** D1, D2, D3, D4, D7 and S1 give no measured effect. D5, D6 and S2 give anecdotes or internal numbers. No source tests a skill, a hook or a reviewer agent on a coding task.
- **Deterministic checks versus prose rules.** D7 says a CLAUDE.md line works most of the time. D5 and R9 argue for grading outcomes and external checks. No source measures a Stop hook against a prompt rule on the same tasks, so this stays a hypothesis.

## Current system and gaps

Findings are from the seven subsystem audits of this working tree. Evidence is kept as the audit wrote it, with some sentences cut. Strengths are listed too. Items under "Could not verify" were not checked by the audit.

### Gates and hooks

How it works today:

- Claude Code wires the hooks from settings.json. Stop runs the Node gate in [hooks/stop-gate.mjs](../hooks/stop-gate.mjs). PreToolUse runs the command guard in [hooks/guard.mjs](../hooks/guard.mjs). PostToolUse runs a syntax check and lint. UserPromptSubmit adds the skill hint and reminders. A separate learn-gate asks for a learn pass every N tool calls.
- The Stop gates read the transcript. An edit counts as unverified when no test or run command follows it. The reply is then checked for marker text (verdict, review line, unverified statement).
- The Python gate in [bossku/gate.py](../bossku/gate.py) adds paste and memory-rule checks, but it runs only when no Node harness is wired.
- The only check that reads a real outcome is the post-edit compiler or syntax check, which uses the exit status.
- The guard is a word-level command filter. Its deny list is also copied into permissions.deny. Its errors fail open.

### Orchestration and agents

How it works today:

- The parent session scopes the work and delegates to seven contracts in agents/: researcher (read-only), planner (tiers by risk), designer (design gate), executor (builds, 5-iteration cap), auditor (Pass, Pass with Notes or Fail), and final-reviewer (MERGE, REVISE or REJECT).
- Medium and large tiers add a brief gate: the orchestrator returns brief_gate: pending and stops. Push, merge and PR wait for the user's go-ahead ([agents/orchestrator.md](../agents/orchestrator.md)).
- [bossku/host_agents.py](../bossku/host_agents.py) renders the same contracts for Codex, OpenCode, Cursor and Devin, with a model per role and read-only locks.
- The brief gate, tier rules and terminal states are prose. No code reads brief_gate.
- [bossku/validate.py](../bossku/validate.py) checks frontmatter, the runtime-core block and Bash on verifying agents. It does not check tiers, gates, terminal states or budgets.

### Benchmarks and evals

How it works today:

- [scripts/benchmark_agent.py](../scripts/benchmark_agent.py) runs headless Claude Code on small Python task folders. It copies the seed into a fresh git repo, runs the agent, then copies the hidden tests in and runs unittest. Pass means every hidden test passes.
- Claude arms use the author's login with a $1 per-run cap. Ollama arms are tokens only.
- Published sets: 10 October 2026 (Claude Haiku and Opus), 1 to 8 October (DeepSeek, Gemma, Nemotron via Ollama), and a 29 October pack comparison. Summaries are recomputed from raw rows and pinned by tests. Excluded runs and infrastructure failures are counted separately.
- The reported gain is memory across two sessions, one model, 22 tasks. Coding is at ceiling for the Claude models.

## Baseline before any change

These numbers were measured in this working tree before any change of this upgrade. They are used as given. Where the inputs disagree, the disagreement is stated.

- **Unit tests:** 897 run, 0 failures (2026-11-11, after the skill text fixes, before any code change of this upgrade). One test, `test_it_syncs_on_opencode_1_idle_and_when_an_opencode_2_run_ends`, failed in three earlier runs and passed in four later ones without being touched, so it looks intermittent.
- **Routing benchmark** (`python scripts/benchmark_routing.py`): 101 of 101 top-1. Conflict: [docs/benchmarks/README.md](benchmarks/README.md) describes this tuned regression check as 84 prompts. The 101 count is as measured here and is not reconciled with that page.
- **Held-out routing** (`python scripts/benchmark_routing_heldout.py --arm now=. --split all`): top-1 93% on the dev half (170 prompts) and 83% on the test half (158 prompts). Conflict: the saved result [benchmarks/results/routing-heldout.json](../benchmarks/results/routing-heldout.json) reports 81.0% (128 of 158) on the test split. The inputs do not explain the difference.
- **Vendored probes** (`benchmarks/routing-heldout/vendored-probes.json`, 790 blind prompts for 248 vendored skills): top-1 46% dev and 42% test; top-3 64% and 63%. The description-only keyword baseline scores 49% and 45% top-1. The `mengto` pack is found (selected or in the top three) for 63 of its 250 prompts.
- **Shipped prompt hint (policy v2)** on the negative sets (`python scripts/benchmark_routing_heldout.py --policy v1 v2 confident_router --prompts <file> --split fresh`): silent on 100 of 100 trivial prompts. Fires on 23% of 120 out-of-catalog prompts. On 173 lure prompts ([benchmarks/routing-heldout/lures.json](../benchmarks/routing-heldout/lures.json)) it shows a hint for 64%, and 30% of the skills it names are right. The `confident_router` policy cuts out-of-catalog fires to 1%, but fires on 20% of trivial prompts and 32% of follow-ups.
- **Published agent runs** (from the benchmarks-and-evals audit; sources as the audit gives them):
  - Coding and HumanEval are at ceiling for the Claude models. Haiku passed 16 of 17 coding tasks without Bossku; Opus passed 17 of 17. Both passed 40 of 40 HumanEval (`benchmarks/results/2026-10-10.json` suites.test and suites.humaneval; `docs/benchmarks/results-2026-10-10.md:105-110` and `:124-129`).
  - The two-session memory tasks are the only clear gain, and only for one model. Haiku: 10 of 22 without Bossku, 16 of 22 with v2.2.0 (+27 points, 95% CI +9 to +45), 15 of 22 with the improved build (+23, CI 0 to +45). Opus: 15, 17 and 16 of 22, with intervals that include zero (`suites.memory-both`; `results-2026-10-10.md:147-150`). One trial per task per setup.
  - Live routing: an acceptable skill was opened in 27 of 60 runs (45%) with DeepSeek V4.1 Flash (`benchmarks/results/routing-live.json`). Skills were opened in 4 of 487 completed coding, harder-task, HumanEval and memory runs with Bossku (`docs/benchmarks/README.md`).
  - The 84-case plugin eval suite (57 should-load, 27 near-miss) has never been run and no results are committed. `evals/README.md` says the format was checked, not run.
  - Cost to re-run the Claude matrix once (3 arms, 1 trial): about $83, computed by the audit from the cost means in `suites.*` (test $15.4 Haiku and $8.8 Opus; HumanEval $17.4 and $9.3; memory-both $20.2 and $11.9). This is an estimate, not a bill. Ollama runs have no dollar cost.

What this baseline can say: the router finds an acceptable skill more often than keyword search on requests it was not tuned on, and the hint stays quiet on trivia. What it cannot say is whether Bossku improves coding correctness for strong models. The coding tasks are at ceiling for the Claude models, the harder Claude runs did not finish, and the only memory gain is one model on 22 tasks with one trial each. Any claim about correctness on strong models needs a new task set where the baseline fails sometimes, and paired runs with several trials.

### Experiments run and not adopted

The route counts in this section, and the "router lab" result in the first table row, come from one-off local runs on a patched copy of the package. The patched copy and its output are not kept in this repository, so these counts cannot be re-run from it. The 1,392 labelled prompts are the 101 routing benchmark cases, the 328 held-out prompts, the 790 vendored probes and the 173 lures. The skill text counts in the table (87 skills with a defect, 78 additions, about 2,100 words) come from the local pass reports, which are not kept here either.

- **Punctuation-tolerant phrase matching.** A trigger phrase next to a comma or full stop never matches today. Matching it changed 83 of 1,392 routes: 12 better, 15 worse. Not shipped.
- **Selection floor without deferred skills.** A user-invoked skill's score sets the floor for the others. Removing it changed 3 routes: 0 better, 1 worse. Not shipped.
- **Curated triggers for vendored skills.** 316 phrases were proposed from the dev half of the vendored probes. Every phrase that fixed a miss also made its skill the wrong first pick in some natural request, across two independent audits. None shipped.
- **Model capability profiles and a strategy selector.** Not built. H1 and H2 support testing whether structure helps weaker models more than stronger ones, but both studied open-weight models inside one agent loop, and no run here measures it for this toolkit. A selector with no measurement behind it would be the kind of complexity the upgrade was meant to avoid. It stays a hypothesis with a planned test.

### Review record

Every reviewer and fixer named here was a model agent, not a person.

- **Per package.** Every code package was built test-first, reviewed by an independent agent and fixed. The first four reviews found 18 required problems (5 P1 and 13 P2); all were reproduced and fixed.
- **Stop gate, four rounds.** A second audit replayed the rewritten gate on 49 real session transcripts. The new error rule had fired 16 times in the Node gate and 11 times in the Python gate, and every time it blocked a turn that held a passing check: the errored command had been denied or aborted and never ran. Such a command now counts as not run. A third audit of that fix found the Node gate printing credentials in its block message (1 P1) and 4 P2. A follow-up package closed what was left, and its own audit found 1 P1 and 3 P2 more, all fixed. Final replay on real data: 13 of the 16 false blocks are gone, and the 3 left are one session whose check really exited 1. The follow-up changed 0 of 1,213 real turn-end verdicts and 0 of 46,686 real commands, and the Node and Python gates cut all 46,686 commands into the same segments.
- **Design packages.** The three reviews asked for changes: 1 P1 and 4 P2 (references), 7 P2 (layout check), 3 P1 and 5 P2 (design direction). The fixers report them fixed. The detail is in [human-centred-design-upgrade.md](human-centred-design-upgrade.md).
- **Pre-release review of the whole change.** Four reviewers (instructions, skills, code and security, release claims and privacy), then one skeptic per finding. The skeptics upheld all 27 serious findings: 10 P1, 15 P2, and 2 they lowered to P3. Several were one problem seen by two reviewers. The main ones: a skill text pass had put the old ask-first rule back into four skills and 78 reference files; the orchestrator contract still asked for brief approval on medium work; a learned skill could still carry `allowed-tools` through an odd line break; one long handoff line pushed every decision out of the session brief; and `bossku remember` mangled `curl --user-agent`. ### Known limits of the gate

- A check started in the background counts when it starts. Its later result is not read. In the real data, 10 verified turn ends rest only on such a check.
- The PowerShell reading rules were checked on made-up input only: the real transcripts hold no PowerShell tool call.
- `bossku evidence` follows the Python gate. On 8 of 50 real transcript tails the Node gate reads the turn differently, because its window restarts after its own push-back.
- The learned-skill secret scan is a pattern list. A single-dash secret flag written in a plain sentence is not caught, and three odd command lines are refused when they hold no secret; a test pins those three.
